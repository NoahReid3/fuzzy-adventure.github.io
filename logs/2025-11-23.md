## 2. Short reference notes for later

### Repository creation checklist

1. Log into GitHub → `New repository`.
2. Choose `Private`, add a descriptive name, optionally initialise with `README.md`.
3. (Optional) Add `.gitignore` templates to keep local-only files out of the repo.
4. After the first commit, clone locally and start working via WSL.

### Handy Git reminders

- `git status` often; a clean tree prevents surprises.
- Empty directories need placeholders such as `.gitkeep`.
- Stage everything in the current directory with `git add .`.
- Use concise, meaningful commit messages; push once a logical chunk is done.

### Markdown cheat sheet refresher

- Heading levels: `# H1`, `## H2`, `### H3`.
- Bullets: `- item`, numbered lists with `1.`.
- Code fences: three backticks with optional language (` ```bash `).
- Bold/italic: `**bold**`, `_italic_`.

### Cursor & AI workflow tips

- **Ask mode**: question-and-answer without file edits.
- **Agent mode**: allow the AI to read, modify, and create files (review diffs before applying).
- Provide context by selecting files or dragging code blocks into the chat.
- Use the built-in Source Control panel to stage, commit, and push directly.

### Future project architecture (teaser)

- **Frontend**: React + TypeScript UI for viewing and editing logs.
- **API layer**: Node/TypeScript service exposing REST endpoints for logs and transcripts.
- **Database**: Postgres storing sessions, transcripts, summaries, and users.
- **AI integration**: LLM summarises transcripts into Markdown.
- **Hosting**: Hetzner VPS running the app, secured with authentication (e.g., Postgres-auth or Supabase/public auth).
