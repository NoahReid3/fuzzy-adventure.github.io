### Understanding the `.git/` hidden folder

### Git: working with empty directories

**Problem:** Git doesn't track empty directories - it only tracks files.

**Solution:** Create a placeholder file inside the directory. Convention is to use `.gitkeep`:

```bash
mkdir logs
touch logs/.gitkeep
git add logs/.gitkeep
git commit -m "Add logs directory"
```

The `.gitkeep` file is just an empty placeholder. The name is a convention (not a Git feature) - you could use any filename, but `.gitkeep` clearly indicates its purpose.

### Git workflow: staging, committing, pushing

**Complete workflow:**

1. **Check status:**
   ```bash
   git status
   ```
   Shows:
   - Untracked files (red, not yet added to Git)
   - Modified files (red, changed but not staged)
   - Staged files (green, ready to commit)

2. **Stage changes:**
   ```bash
   git add .           # stage everything in current directory
   git add file.txt   # stage a specific file
   git stage .        # same as git add
   ```

3. **Commit:**
   ```bash
   git commit                    # opens editor (Nano) to write message
   git commit -m "Your message"  # commit with message in one command
   ```

4. **Push to GitHub:**
   ```bash
   git push
   ```
   Sends your local commits to the remote repository (GitHub).

**When to commit:**
- Even as a solo developer, commit frequently for:
  - Backup (if laptop is lost, code is safe on GitHub)
  - History (see what you did and when)
  - Practice (good habits for working with others later)

### Understanding diffs

A "diff" shows what changed between two versions of a file.

**In Cursor (before applying AI changes):**
- Shows what the AI wants to change
- Red lines with `-` = lines to be removed
- Green lines with `+` = lines to be added
- If a line changes, it shows as both removal and addition

**In Git:**
- `git diff` shows uncommitted changes
- `git diff HEAD~1` shows changes in last commit
- GitHub shows diffs when viewing commits or pull requests

**Reading a diff:**
- Left side (red, `-`) = old version, what's being removed
- Right side (green, `+`) = new version, what's being added
- Context lines (unchanged) help you understand where changes are

### File naming best practices

**Good practices:**
- Use descriptive names that explain what the file contains
- Use consistent naming conventions
- For dates: `YYYY-MM-DD` format sorts chronologically (e.g., `2025-11-23.md`)
- Use dashes (`-`) or underscores (`_`) instead of spaces
- Include file extensions (`.md`, `.txt`, `.js`, etc.)

**Examples:**
- ✅ `2025-11-23.md` (sorts properly, clear date)
- ✅ `week-one-log.md` (descriptive, uses dashes)
- ❌ `week 1 log.md` (spaces can cause issues)
- ❌ `Week1Log.md` (harder to read, inconsistent)

**For this project:**
- Log files: `YYYY-MM-DD.md` (e.g., `2025-11-16.md`, `2025-11-23.md`)
- Transcripts: `transcripts.txt` (simple, descriptive)

### Localhost and port forwarding

**What is localhost?**
- `localhost` is the address that refers to your own computer
- When developing web apps, you run a server on your machine
- Access it in browser at `localhost:PORT` (e.g., `localhost:3000`)

**Ports:**
- Different services use different port numbers
- Common ports: 3000 (React dev server), 8000 (Python), 5432 (PostgreSQL)
- Port is like a "door" - each service has its own door number

**Port forwarding:**
- When working in WSL, services run in Linux
- Browser runs on Windows
- Port forwarding connects them so browser can access Linux services
- Cursor/VS Code handles this automatically

**Example workflow (future):**
1. Start web server in terminal: `npm start` (runs on localhost:3000)
2. Open browser: go to `http://localhost:3000`
3. See your web app running locally
4. Make changes, see them update automatically (hot reload)

### Terminal paste shortcuts

**Important:** Different applications use different shortcuts!

- **Most applications:** `Ctrl+C` = copy, `Ctrl+V` = paste
- **Terminal (Linux/WSL):** `Ctrl+Shift+C` = copy, `Ctrl+Shift+V` = paste
- **Some terminals:** Can be configured to use `Ctrl+C`/`Ctrl+V`

**Why the difference?**
- In terminal, `Ctrl+C` is used to interrupt/cancel commands
- So paste uses `Ctrl+Shift+V` to avoid conflicts
- You can configure your terminal settings to change this if you prefer

**Tips:**
- Right-click in terminal often shows context menu with copy/paste
- Can also use middle mouse button to paste in some terminals
- Check your terminal settings to customize shortcuts

### Git compression and efficiency

When you `git push`, you might see output about:
- "Compressing objects"
- "Writing objects"
- Numbers and hashes

**What's happening:**
- Git compresses data before sending over network
- Makes transfers faster and uses less bandwidth
- The "objects" are Git's internal way of storing files and history
- You don't need to understand the details, but know that Git is efficient

**Takeaway:** Git is smart about transferring data - it only sends what's needed and compresses it to save time and bandwidth.
