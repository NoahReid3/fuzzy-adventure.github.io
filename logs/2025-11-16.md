## 2. Short reference notes for later

You can paste/print this as your "cheat sheet".

### Git & GitHub

#### Git

A version control system that tracks changes to files (especially code) over time.

Stores complete history (commits) and supports branches, merging, and collaboration.

#### GitHub

A website that hosts Git repositories.

Used by individuals and companies to store code, review changes, and collaborate.

Repos can be public (anyone can see the code) or private (restricted access).

#### Key terms

- **Repository (repo)** – project + its history
- **Branch** – parallel line of development (e.g. main, feature/login)
- **Commit** – a snapshot of changes, with a message explaining what changed and why
- **Diff** – shows exactly what lines changed (removed vs added)
- **Remote** – the server copy on GitHub (origin)
- **Local** – your copy on your machine

#### Good practice

- Use clear, meaningful commit messages
- Don't commit straight to main; use feature branches
- Prefer squash and merge PRs so main has a clean history

#### Basic Git workflow (local ↔ GitHub)

On your machine (in the repo directory):

1. **Pull latest code**
   ```bash
   git pull
   ```

2. **Make changes**
   - Edit files (e.g. with Nano, or an IDE)

3. **Check status**
   ```bash
   git status
   ```

4. **Stage changes**
   ```bash
   git add .      # stage everything
   # or
   git add file-name
   ```

5. **Commit changes**
   ```bash
   git commit -m "Short, clear description of what you changed"
   ```

6. **Push to GitHub**
   ```bash
   git push
   ```

On GitHub: open a pull request from your branch into main, get it reviewed, and squash & merge.

### WSL, Linux & Windows Terminal

#### WSL (Windows Subsystem for Linux)

Lets you run a full Linux environment inside Windows.

Installed via PowerShell with something like:

```bash
wsl --install -d Ubuntu-22.04
```

Linux distribution used: Ubuntu 22.04.

You set a Linux username and password (important: not easily reset).

#### Windows Terminal

Modern terminal app with tabs and profiles.

Configure default profile to open directly into Ubuntu (WSL) for development.

#### Terminal basics (Bash in Ubuntu)

Prompt looks like:

```
noah@nolaptop:~$
```

- `noah` = username
- `nolaptop` = machine name
- `~` = home directory

**Useful commands:**

- `ls` – list files in current directory
- `cd directory-name` – change directory
- `cd ~` – go to home
- `cd ..` – go up one level
- `mkdir name` – create a new folder
- `clear` – clear the terminal output

**Example sequence to set up projects:**

```bash
mkdir projects
cd projects
```

#### sudo and apt (Linux administration)

- **sudo** – run a command with admin (root) privileges, e.g.:
  ```bash
  sudo apt update
  ```
- **apt** – package manager for installing/updating software on Ubuntu
- `sudo apt update` refreshes the list of available packages

### GitHub CLI and cloning repos

#### GitHub CLI (gh)

Terminal tool to interact with GitHub.

**Login:**

```bash
gh auth login
```

Choose github.com, HTTPS, log in with a web browser, paste the one-time code, authorise.

**Cloning a repo** (copying it from GitHub to your machine):

```bash
cd ~/projects
git clone https://github.com/uncommon-org/identity-provider.git   # example URL
cd identity-provider
ls
```

### Editing files with Nano

**Open a file:**

```bash
nano README.md
```

Move with arrow keys, type to edit.

**Save and exit:**

`Ctrl + X` → press `Y` to save → `Enter` to confirm filename.

### TypeScript vs JavaScript (high level)

#### JavaScript

Language that browsers and Node.js actually run.

#### TypeScript

A "superset" of JavaScript with extra features and static types.

You write TypeScript, then a tool transpiles it into JavaScript.

Gives better safety and developer experience, especially in large codebases.
